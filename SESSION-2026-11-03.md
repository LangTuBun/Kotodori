### `src/data/reading-passages.ts`

Full reading-body transcription data for **53 exercises**, grouped into **194 paragraphs/listing groups** and **746 study units**. A unit can be a sentence, a few closely related short sentences, a heading or a table row; it is not necessarily one Japanese grammatical sentence.

Coverage: Chapters 16–33, exercises 1–3, except **23-1**, which is not present in the supplied photos. Chapter 16 exercise 1 is included in this data too, so it no longer needs a separate UI implementation.

Structure:

```ts
interface ReadingSentence {
  jp: string
  translation: { en: string; vi: string }
  grammarIds: string[]
}
type ReadingParagraph = ReadingSentence[]
const readingPassages: Record<string, ReadingParagraph[]>
```

Keys are `chapter-exercise`, for example `readingPassages['33-2']`.

The local `s(jp, en, vi, ...grammarNumbers)` helper creates each unit and converts numeric references such as `144` into `g_144`. The file imports only a type from `sentence-breakdowns`, so Node 24 can read it directly for data checks.

The transcriptions include letters, chats, stories, notices, product listings, recipe steps, course descriptions, schedules, survey wording/values, studio prices, hotel plans and continuation pages. English/Vietnamese translations and selected grammar references were authored manually. Source photos were viewed while transcribing. This is drafted content: it still needs final proofreading and grammar-reference validation. Ordinary comprehension answer options and diagram geometry have not all been converted into native-text quiz data.

Some apparent oddities are printed in the sources and should be checked against the photo before changing them. Examples: Chapter 19’s weekend time row, Chapter 26’s earthquake time and the date/month wording of the Hokkaido forum post. The cultural/legal/health/emergency statements are book reading material, not independently verified current guidance. Do not claim an external fact-check occurred.

### `src/lib/reading-vocabulary.ts`

Draft pure matcher for the reader’s dictionary forms:

- Uses `Intl.Segmenter('ja', { granularity: 'word' })` boundaries to avoid unreliable kana matches inside another word.
- Ignores one-character forms, favours longer matches, removes overlaps and deduplicates dictionary headwords.
- Returns the matched form, dictionary entry and text offsets.

Needs meaningful tests for kana boundaries, compounds, overlapping forms, repeated words and conjugated forms. Dictionary matches do not provide automatic contextual sense disambiguation or complete morphological parsing; the UI explicitly distinguishes dictionary meanings from the authored passage translation.
